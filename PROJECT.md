## 1. Что это за проект

Автоматизация подкаста бизнес-блогера (Юлия Алёхина - стратег по бизнесу, автор деловых книг). Задача: Юлия делает только творческую часть (записывает голос, пишет тексты, готовит PDF), а публикация, обработка, сбор аудитории и продажи идут автоматически.

Главный принцип: **записал один раз → система разнесла по каналам, собрала аудиторию, продала.**

Воронка: подкаст (Podster → площадки + Telegram-канал) → человек приходит в бота → бесплатный PDF / квиз → платные гайды + подписка на закрытый канал.

## 4. Объём - ФАЗА 1 (входит в 45к)

### 4.1. Распространение подкаста
- Podster (хостинг аудио) → RSS → авто-раздача на VK, Яндекс.Музыка, Apple, Spotify (нативно в Podster, разовая настройка RSS на каждой площадке).
- RSS обновился → авто-пост-анонс в открытый Telegram-канал (текст из полей RSS: название, описание, ссылка + призыв к боту).

### 4.2. Обработка аудио (ffmpeg, БЕЗ нейронки)
- Основной подкаст: наложение интро, фоновой музыки-подложки, заставки (звук микрофона), нормализация громкости. Шаблонный ffmpeg-пайплайн: `интро + [голос микс музыка_фон] + аутро`. Ассеты (интро, музыка) даёт клиент.
- Аудиобонусы и голосовые разборы для закрытого канала - обработка НЕ нужна (сырые тренерские записи).
- Схема: клиент кидает сырой голос → ffmpeg-пайплайн → готовый эпизод → Podster.

### 4.3. Генерация PDF (WeasyPrint, БЕЗ нейронки)
- Клиент даёт готовый ТЕКСТ → система заливает в HTML-шаблон (логотип, фирменный стиль, шрифт, цвета) → рендер в PDF. Чистая вёрстка по шаблону, не генерация контента. Инструмент: WeasyPrint (HTML+CSS → PDF).

### 4.4. Планировщик отложенной публикации
- Клиент грузит эпизоды пачкой → система публикует по расписанию («сетка», отложенная публикация). APScheduler + хранилище.

### 4.5. Telegram-бот (aiogram 3.x) - сценарии
1. **/start** - приветствие + кнопки: PDF-бонус, Тест, Закрытый канал, Магазин.
2. **PDF-бонус** - (опц. запрос email) → выдать ссылку/файл → записать контакт в Sheets → предложить закрытый канал.
3. **Квиз** - 5 вопросов на бренд/тему → результат → записать в Sheets → предложить закрытый канал.
4. **Закрытый канал** - оплата → бот выдаёт одноразовый invite в приватный TG-канал. Есть 1-дневный бесплатный триал.
5. **Магазин** - список PDF-гайдов с ценами → оплата → бот отдаёт файл.
6. **/admin** - статистика (подписчики, продажи, запросы PDF за неделю). Whitelist по Telegram ID владельца.

### 4.6. Хранилища данных
- **Google Sheets** (витрина для клиента): База контактов (TG ID, имя, email, дата, источник, результат квиза), Продажи (дата, TG ID, товар, сумма, статус), Участники марафона, Игры/амбассадоры.
- **Внутренняя БД (PostgreSQL)**: источник правды - подписки, обработанные оплаты (идемпотентность), состояние. Sheets - копия для владельца, дедуп держим в БД.
- **Notion** (пульт контента): база «Эпизоды» - Название, Статус (Идея/Сценарий/Запись/Монтаж/Контент готов/Опубликован), Сезон, Бренд, Дата выхода, Ссылка на аудио, Ссылка на расшифровку, Пост для Telegram, Пост для VK, Текст для Дзен, PDF-бонус, Темы для клипов. Смена статуса на «Контент готов» → уведомление владельцу.

### 4.7. Монетизация (цифры от клиента)
- Подписка на закрытый канал: ~200 ₽/мес (VK Donut в исходном ТЗ; по факту - Telegram-нативно, см. раздел 5).
- PDF-гайды: 20-30 ₽ за штуку (дёшево намеренно - подписка выгоднее разовой покупки, толкает в подписку).
- 1-дневный бесплатный триал закрытого канала (заход без оплаты, потом конверсия в платную подписку).
- Логика воронки клиента: человек хочет купить одну «бумажку» за 20-30 ₽ → видит что за 200 ₽/мес получит десятки гайдов → берёт подписку.

## 5. КЛЮЧЕВОЕ РЕШЕНИЕ: оплаты Telegram-нативно, НЕ через VK

На созвоне клиент отдала выбор механизма исполнителю («не обязательно привязка к ВК»). Исходное ТЗ требовало VK Donut + VK Товары - это создавало боль: атрибуция «кто оплатил на VK» к Telegram-юзеру, отсутствие вебхука Donut, ручной мост.

**Решение:** оплаты внутри Telegram.
- Приём денег: Telegram Stars или платёжный провайдер (ЮKassa) через `sendInvoice`. Бот сразу знает кто и что оплатил → мгновенная автовыдача PDF/доступа. Атрибуция не нужна.
- Закрытый канал = приватный Telegram-канал. Бот генерит одноразовый invite (`createChatInviteLink`, `member_limit=1`, `expire_date`) после оплаты. По окончании подписки бот кикает (APScheduler свод активных подписок → бан просроченных).
- 1-дневный триал - на своей БД подписок.
- VK остаётся ТОЛЬКО как площадка для RSS-подкаста, не для денег.

Это проще, надёжнее, целиком под контролем исполнителя. Если клиент всё же захочет VK-продажи - делается отдельно.

## 6. Объём - ОТДЕЛЬНАЯ ПЛАТА (НЕ в 45к, апселлы, фаза 2+)

Держать как отдельные чеки, не пускать в базу:
- **Игра «бизнес-покер»** (моделирование бизнес-стратегии в боте). Цену привязывать к механике: против бота/одна сессия/кнопками = 5-10к; между людьми/рейтинг/реалтайм = 25-40к+. Выяснить: игрок vs бот или vs люди; одна партия или сохранение прогресса; реалтайм или пошагово.
- **Рилсы / AI-видео** (говорящая голова, аватар, генерация из сценария). Нужны API-ключи нейросетей + ежемесячные токены. Instagram душит ботов → загрузка ручная, генерация авто. Единственное место в проекте, где нужна нейронка.
- **Лендинг** под подкасты.
- **Марафоны, бизнес-сессии.**
- **Продажа книг** (клиент пишет деловую литературу).
- **YouTube-выгрузка.**

## 7. Технический стек

| Слой | Инструмент | Зачем |
|---|---|---|
| Бот | aiogram 3.x (async) | ядро, FSM |
| Веб-сервер / вебхуки | FastAPI + uvicorn | приём платёжных вебхуков, health |
| HTTP-клиент | httpx (async) | Notion/внешние API |
| Планировщик | APScheduler | RSS-опрос, отложенная публикация, ревокация подписок |
| Обработка аудио | ffmpeg | интро/музыка/заставка/нормализация |
| Генерация PDF | WeasyPrint | текст → стилизованный PDF |
| Google Sheets | gspread + google-auth (service account) | база контактов/продаж |
| Notion | notion-client / REST | база «Эпизоды», уведомления |
| RSS | feedparser | новые эпизоды Podster |
| Оплаты | Telegram sendInvoice (Stars / ЮKassa) | приём денег в боте |
| Внутренняя БД | PostgreSQL + asyncpg (или SQLAlchemy 2.0 async) | подписки, идемпотентность, состояние |
| FSM-хранилище | Redis | состояние переживает рестарт |
| Конфиг/секреты | pydantic-settings + .env | токены не в коде |
| Логи | loguru | разбор сбоев |
| Деплой | systemd (или Docker Compose) на VPS | круглосуточно |
| HTTPS для вебхуков | Caddy (авто-TLS) | VK/платёжный callback требует HTTPS |

БЕЗ нейронки: PDF (шаблон) и аудио (ffmpeg) - детерминированные пайплайны, ноль затрат на токены. Нейронка только в рилсах (фаза 2).

Установленные скиллы под проект: `gws-sheets`, `notion-api`, `fastapi`.

- Секреты в .env, не в коде, не в git. В графе/памяти - только REDACTED.

## 12. Порядок работ

1. **Первый шаг:** клиент шлёт 1 голосовой образец → собрать ffmpeg-пайплайн обработки аудио → клиент начинает копить бэклог 2-3 тестовых эпизодов пока идёт разработка.
2. Скелет проекта, конфиг, каркас бота.
3. Обработка аудио + генерация PDF (шаблоны).
4. Бот: сценарии 1-6, FSM, оплаты Telegram-нативно, закрытый канал (invite + ревокация).
5. Интеграции: Google Sheets (service account), Notion (база + уведомления), RSS → Telegram-анонсы, планировщик публикации.
6. Деплой на VPS (systemd/Docker + Caddy), .env.
7. Проверка всей цепочки: аудио → Podster → анонс → бот → PDF/квиз/оплата → выдача/доступ → запись в Sheets.
8. Передача + инструкция по администрированию.

Фаза 2 (отдельные чеки): игра, рилсы, лендинг, марафоны, книги, YouTube.
