# Настройка оплат (ЮKassa external checkout)

Оплаты идут через **внешний чекаут ЮKassa**: бот создаёт платёж по REST API, отдаёт клиенту ссылку `confirmation_url`, а после оплаты ЮKassa шлёт **вебхук** на наш сервер — бот проверяет статус и автоматически выдаёт доступ/файл. Бот всегда знает, кто и что оплатил (по `metadata.tg_id`), атрибуция не нужна.

## Что нужно от клиента

1. Завести приём платежей в **ЮKassa** на единую почту проекта (yookassa.ru → «для бизнеса / самозанятых»), пройти модерацию. ЮKassa поддерживает самозанятых.
2. В ЛК ЮKassa взять данные магазина: **shopId** и **секретный ключ** (Настройки → API-ключи; для боевого приёма — выпустить live-ключ, для проверки есть тестовый магазин).
3. Прислать эти два значения — их кладём в `.env` на сервере (в коде и git их нет).

`.env`:
```
YOOKASSA_SHOP_ID=<shopId>
YOOKASSA_SECRET_KEY=<секретный ключ live_ или test_>
PAYMENT_CURRENCY=RUB
```

Суммы в коде — рубли; ЮKassa принимает их как `value` в формате `"790.00"`.

## Вебхук (обязательно)

После поднятия домена (Caddy даёт HTTPS автоматически) зарегистрировать URL уведомлений в ЛК ЮKassa (Настройки → HTTP-уведомления):

```
https://<домен>/payments/yookassa
```

Событие — **`payment.succeeded`**. Без вебхука бот не узнает об оплате и не выдаст доступ.

## Как это работает в коде

- `bot/services/yookassa.py` — `create_payment()` (создаёт платёж, возвращает `confirmation_url`) и `get_payment()` (перезапрос статуса).
- `web/app.py` — эндпоинт `POST /payments/yookassa`: принимает уведомление, **перезапрашивает платёж по id через API ЮKassa** (не доверяет телу запроса — защита от подделки), проверяет `status == succeeded` и `paid`, затем вызывает выдачу.
- `bot/services/fulfillment.py` — идемпотентная выдача по `payment_id` (таблица `processed_payments`, повторный вебхук не задваивает). Виды платежей (`metadata.kind`): `sub` (подписка, поле `days` = 30/90), `season` (архив сезона), `workbook` (рабочая тетрадь), `all` (все сезоны). Подписка — плюс одноразовый invite в закрытый канал; всё пишется в БД и Google Sheets («Продажи»).

## Проверка

Тестовым магазином ЮKassa (`test_`-ключ): в боте нажать «Оформить подписку» → перейти по ссылке → оплатить тестовой картой → веббук → бот выдаёт invite/файл. Затем переключить на боевой ключ.

## Про запасной вариант (Telegram Stars)

Текущая реализация — только ЮKassa REST. Stars потребуют отдельной ветки на `sendInvoice` (в этой версии не подключены). Если ЮKassa окажется недоступна для цифровых товаров в регионе — заводим Stars отдельной задачей.
